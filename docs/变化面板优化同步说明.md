# 变化面板优化同步说明

本次优化已合入 `main`。变化面板先加载修订与执行状态，展开处理详情后再读取完整上下文；已结束记录停止轮询，可手动刷新。原事件证据、提交核对及重试关联规则保持不变。

## 同步代码

先提交或妥善保存自己的未完成改动，不要强制覆盖工作区。

同步主分支：

```bash
git fetch origin
git switch main
git pull --ff-only origin main
```

正在自己的任务分支开发时，可在保存改动并执行 `git fetch origin` 后运行 `git merge origin/main`；如有冲突，重点核对公共接口和生成客户端。

## 更新本地数据库

在项目根目录执行。保留自己的 `.env` 和数据库，不复制其他人的真实聊天或密钥。先停止本地处理任务及后端，确保没有运行中的分析，再执行迁移。

```bash
docker compose up -d --wait mysql
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql --user="$MYSQL_USER" "$MYSQL_DATABASE" --execute="SHOW COLUMNS FROM processing_attempts LIKE '\''event_link_hints'\''"'
```

如果上面的查询没有返回字段，则执行：

```bash
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql --user="$MYSQL_USER" "$MYSQL_DATABASE"' < backend/migrations/002_event_link_hints.sql
```

如果字段已存在，不要重复执行 `002`。新环境须先按 README 初始化消息、事件及运行记录，并执行 `001_processing_attempts.sql`，再执行 `002`。

迁移只增加自动维护的轻量关联提示列，不删除阶段、收据或业务记录。存量计算可能锁表，耗时随数据量变化。未迁移仍可查询，但执行关联会使用较慢的兼容路径；应用不会自动迁移。

## 启动与检查

沿用 README 安装环境。本次没有新增 Python 或 npm 依赖；已提交更新后的 OpenAPI 与前端生成客户端，无须手工修改生成文件。

后端，在项目根目录启动：

```bash
.venv/bin/python -m uvicorn dake.main:app --host 127.0.0.1 --port 8001
```

前端，在另一个终端启动：

```bash
cd web
npm run dev
```

打开 `http://localhost:8000`，选中已有事件并打开变化面板，确认：

- 变化时间线和失败／待核实提示正常显示。
- 处理详情默认折叠，展开后才读取完整记录。
- 切换事件后不混入前一个事件的记录。
- 没有未结束的关联执行或任务时停止轮询，点击刷新仍能读取最新结果。

不要为了检查页面而清空数据库或重新清洗真实客户。没有本地数据时先使用合成测试；其他客户的真实模型处理遵循已有授权范围。

## 验证结果与边界

本机三个样例首屏接口由约 18–20 秒降至约 1.1–1.4 秒，响应由约 4–5 MB 降至约 50–126 KB。两个样例的新旧完整响应已逐字段核对一致。这些是当前本地数据量的实测，不是所有环境的延迟承诺。

已通过后端常规测试、独立 MySQL 的执行与面板测试、MySQL 消息及任务存储测试，以及前端 lint、build、合成测试和真实后端只读浏览器检查。生成列仍需扫描客户范围内的轻量提示；更大规模的数据需要继续评估关系索引方案。
